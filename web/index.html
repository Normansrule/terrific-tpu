How it works

Four beats of a systolic heart

Scroll. The array on the left follows along, running the same timing rules as the Verilog: vector v is inside PE(k, n) on cycle v + k + n.

01 · LDW

Weights move in, and stay.

Four rows of weights shift down from the top, one per clock tick. Then they sit still inside the 16 processing elements (PEs) for the whole batch. Weight-stationary: every weight fetched once, used many times.

02 · skew

Inputs enter on a staircase.

Each row's input waits one extra cycle more than the row above. That delay line (skew.v) is what makes every number arrive at exactly the right PE at exactly the right moment.

03 · MMUL

A diagonal wave does the math.

Every tick, every busy PE multiplies its input by its weight, adds the sum from above, and passes both on. Inputs flow right, sums flow down, and a diagonal wavefront sweeps across the grid.

04 · ACT

Results drain, add, activate.

Finished sums leave the bottom 2N − 1 cycles later, get lined back up, land in 32-bit accumulators, then pass through ReLU and a shift back to 8 bits for the next layer.

Run it yourself

Four commands to a working TPU.

Ubuntu or Windows Subsystem for Linux (WSL). Everything is open-source: Icarus Verilog, Yosys, Python, Node.js.

1 · Install and test

# tools
$ sudo apt install -y iverilog gtkwave yosys python3 nodejs make git
# get it and prove it works (demos, 400 random programs, 16 planted bugs)
$ git clone https://github.com/Normansrule/terrific-tpu.git
$ cd terrific-tpu && make test

2 · See it

# this website, locally, at http://localhost:8000/web/
$ make serve
# the waveform in GTKWave
$ make wave

3 · Push it into new places

# image filter, quantum search, graph triangles
$ make apps
$ python3 tools/golden_model.py --demo grover --marked 1
# five experiments: CSV files + charts
$ make experiments

4 · Take it toward silicon

# real SkyWater 130 nm area with Yosys
$ export SKY130_LIB=~/pdk/sky130A/libs.ref/sky130_fd_sc_hd/lib/sky130_fd_sc_hd__tt_025C_1v80.lib
$ make synth && make diagrams
